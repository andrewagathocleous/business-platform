# ADR-0003: Tenant isolation through membership checks and PostgreSQL RLS

- Status: accepted
- Date: 2026-10-19

## Decision

- Company-scoped routes live under `/api/c/:companyId/...`. A guard verifies an **active** membership (or platform owner) for that company and loads permissions. The company id from the URL is never used without that check.
- Every company-scoped table has a non-null `company_id`, and RLS is enabled **and forced**:
  `USING (company_id = app_current_company())` and `WITH CHECK (company_id = app_current_company())`.
  `app_current_company()` is `NULLIF(current_setting('app.company_id', true), '')::uuid`. The `NULLIF` is needed because after a transaction-local `set_config` the setting reverts to an empty string rather than NULL.
- The application connects as `bp_app`: `LOGIN NOSUPERUSER NOBYPASSRLS`, not the table owner. Migrations run as `bp_owner`.
- Tenant context is set **per transaction** with `set_config('app.company_id', $1, true)` inside an interactive Prisma transaction. That keeps it pool-safe, because the setting never outlives the transaction. All company-scoped data access goes through `TenantDb.run(ctx, tx => …)`.
- Identity and tenancy tables (users, identities, sessions, companies, memberships, roles) are not RLS-scoped by company. Only the identity and tenancy services touch them, and every access is explicitly checked.
- The `job` queue table is infrastructure without RLS. Workers set the job's company context before touching business tables.
- Uniqueness constraints include `company_id` (for example `(company_id, connection_id, external_id)`).
- Stored files sit under `companies/<companyId>/...` keys generated by the server. Downloads look up the file record through RLS first.

## Consequences

- Forgetting a `where company_id` filter returns nothing instead of leaking data.
- Cross-company platform-owner views have to iterate over companies or use dedicated, audited platform services.
- Integration tests must connect as `bp_app`, not as a superuser, or the RLS tests prove nothing.
